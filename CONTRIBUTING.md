# Contributing

Thanks for contributing to Quran Render. Read the [English README](README.en.md)
(or [Indonesian README](README.md)) and start with the technical overview in
[`docs/engineering/README.en.md`](docs/engineering/README.en.md) (Indonesian
originals: [`01_TECHNICAL_HANDOFF.md`](docs/engineering/01_TECHNICAL_HANDOFF.md)
and [`07_BUILD_DAN_TEST.md`](docs/engineering/07_BUILD_DAN_TEST.md)). Core
project rules that must not be broken:

- **Clean-room:** do not copy code, assets, UI strings, or designs from Quran Caption (CC BY-NC 4.0).
- **Verbatim Quranic text:** Arabic text is never modified or generated by AI.
- **Renderer isolation:** the renderer runs with `sandbox` and `contextIsolation` (no Node access); all disk/network/FFmpeg access goes through `window.api`.
- **Single render path:** preview and export use the same pure Remotion composition.
- **Database migrations:** only append to `MIGRATIONS` in `src/main/db.ts`.
- **Bilingual UI:** UI strings live in Indonesian (`t('...')`) with matching English entries in `src/shared/i18n/en/`.
- **Design tokens:** use `qr-*` classes and CSS tokens from `design/system/`.

## Development

Prerequisites: Node.js 22+ (macOS or Windows).

```bash
npm install
npm run dev          # app with hot reload
npm run typecheck    # must be clean
npm test             # Vitest, only src/shared/*.test.ts
npm run build
npm run lint:design  # qr-* classes and CSS tokens must be defined
npm run lint:a11y    # accessible names, labels, contrast tokens
```

Use separate test data while developing:

```bash
QR_USER_DATA=/tmp/qr-dev npm run dev
```

## Pull requests

- Keep changes small and focused.
- Run `npm run typecheck` and `npm test` before opening a PR; CI runs the same
  checks plus `lint:design` and `lint:a11y`.
- Follow the style of the surrounding code. Comments explain *why*, not *what*.
- Add a `CHANGELOG.md` entry for user-visible changes.
- Do not change Quranic text, and do not add living-creature imagery, music
  icons, or Arabic text as decoration.
